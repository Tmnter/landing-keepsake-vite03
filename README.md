# Landing Page — Keepsake (Vite 03)

Сучасний, адаптивний та оптимізований лендинг, створений із використанням передових інструментів фронтенд-розробки. Проєкт фокусується на високій швидкості завантаження, дотриманні методології БЕМ та чистоті коду.

## 🛠 Вимоги до середовища та команди (NPM скрипти)

Для роботи з проєктом на вашому комп'ютері знадобляться Node.js та npm. Основні команди:

* `npm install` — встановлення всіх залежностей проєкту.
* `npm run dev` — запуск локального сервера розробки з Hot Module Replacement (HMR).
* `npm run build` — компіляція проєкту та збірка оптимізованої версії для продакшну у папку `dist`.
* `npm run preview` — попередній перегляд зібраної версії проєкту локально.
* `npm run format` — форматування всього коду проєкту за допомогою Prettier.
* `npm run lint` — запуск перевірки код-стайлу за допомогою лінтерів.
* `npm run images` — генерація сучасних форматів зображень та адаптивних розмірів на базі `sharp`.

## 📂 Архітектура та структура проєкту

Проєкт структурований за модульним принципом із використанням препроцесорів **Pug** та **SCSS**.

* **`src/`** — основна папка з вихідним кодом:
  * **`pug/`** — шаблони сторінок, розбиті на компоненти. Використовується механізм `extends` та `include`, а також кастомний міксин `+picture` для адаптивного виводу зображень.
  * **`styles/`** — SCSS-стилі, організовані за модульною архітектурою:
    * `abstracts/` — змінні, мапи брейкпоінтів та міксини (наприклад, медіазапити mobile-first через `map` та `@content`).
    * `components/` — окремі файли стилів для БЕМ-блоків.
    * `main.scss` — єдина точка входу, що реекспортує парціали через `@forward`.
  * **`images-src/`** — вихідні растрові зображення для оптимізації.

## 🧰 Використані інструменти та їх призначення

1. **Vite** — швидкий збирач проєкту та локальний сервер для розробки.
2. **Pug** — HTML-препроцесор для зручної та модульної структури розмітки.
3. **SCSS (Sass)** — CSS-препроцесор із підтримкою змінних, міксинів та модульної архітектури (`@use`, `@forward`).
4. **BEM (Block, Element, Modifier)** — методологія організації CSS-класів для уникнення конфліктів каскаду та забезпечення плоскої структури селекторів (вкладеність не глибше 3 рівнів).
5. **PostCSS & Autoprefixer** — автоматичне додавання вендорних префіксів до CSS-властивостей на основі цільових браузерів.
6. **Prettier** — автоматичний форматувальник коду (включно з плагіном для Pug).
7. **Stylelint** — лінтер для перевірки дотримання правил написання SCSS та БЕМ-патернів.
8. **Husky & lint-staged** — інструменти автоматичного контролю якості коду перед створенням комітів у Git.

## 🌐 Цільові браузери (Browserslist) та оптимізація

Для проєкту налаштована цільова конфігурація браузерів через `.browserslistrc`:
* `> 0.5%`
* `last 2 versions`
* `not dead`

### Порівняння розмірів файлів до та після оптимізації:

| Ресурс / Файл | До оптимізації | Після оптимізації (AVIF / WebP / Minified) | Покращення / Економія |
| :--- | :--- | :--- | :--- |
| **Головне фото (Hero)** | ~1.2 MB (JPEG) | ~95 KB (AVIF) / ~140 KB (WebP) | **~90% менше** |
| **Картки робіт (Комплект)** | ~3.5 MB (JPEG) | ~320 KB (AVIF/WebP srcset) | **~91% менше** |
| **Головний файл стилів (CSS)** | ~45 KB (сирий SCSS) | ~12 KB (мінімізований CSS) | **~73% менше** |
